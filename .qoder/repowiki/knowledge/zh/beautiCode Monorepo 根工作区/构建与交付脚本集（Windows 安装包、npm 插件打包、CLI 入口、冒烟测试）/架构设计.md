本目录是 monorepo 的脚本中心，按职责划分为四类：
- CLI 入口：`beauticode.mjs` 通过 `import()` 动态加载 `packages/core/dist/index.js` 和 `packages/adapter-codex/dist/index.js`，解析 `--port/--discover/--data-root` 等参数后分派到 `apply-image|apply-video|clear|status|probe|watch|discover` 等子命令，离线模式使用 `BackgroundStore + ApplyTransaction`，在线模式通过 adapter 调用 CDP。
- 插件交付链：`pack-dsh-plugin.mjs` 调用 `npm run build -w @beauticode/core && -w @beauticode/adapter-dsh`，将 `integrations/deepseek-harness` 源码与 vendored core/adapter 拷贝到 `artifacts/dsh-plugin/`，重写 import 路径并可选 `npm publish`。
- Windows 安装包链：`build-windows-installer.ps1` 作为总控，执行 `npm run build` → 下载并 SHA256 校验固定版本 Node.js（24.18.0）→ 将 `apps/tray`、`packages/*`、`integrations/deepseek-harness`、`scripts` 中列出的文件复制到 `artifacts/windows/stage` → 用 Inno Setup (`installer/windows/beauticode.iss`) 编译为 `beautiCode-Setup-*.exe`；配套 `start-beauticode.ps1`、`start-beauticode-engine.ps1`、`codex-launch.ps1`、`install-dsh-plugin.ps1`、`install-desktop-shortcut.ps1` 构成运行时启动与安装流程。
- 测试与工具：`test-runner.mjs` 在 Windows 下把 `TMP/TEMP` 指向长路径再 `spawn` 实际测试命令；`live-smoke.mjs` 基于 adapter 对真实 Codex CDP 端口执行 probe → dual-lock → bad-media → apply-image/video → clear 的端到端冒烟；`copy-renderer-assets.mjs` 供 `adapter-codex` 构建时复制渲染资源。
依赖方向单向向外：脚本只读仓库根下的 `packages/`、`integrations/`、`assets/`、`apps/`，不反向被业务代码引用；CI 通过 `.github/workflows/ci.yml` 中的「Parse JavaScript entry points」和「Parse PowerShell launchers」矩阵扫描这些文件以做语法检查。
