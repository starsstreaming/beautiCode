- 所有 Node 脚本使用 ESM（`.mjs`），并通过 `fileURLToPath(import.meta.url)` 计算相对仓库根的路径，再 `pathToFileURL(...).href` 动态 `import()` 对应 `packages/*/dist/index.js`。
- CLI 脚本统一采用 `parseArgs(argv) → main() → finish(code)` 三段式结构，参数校验失败抛错并由顶层 `try/catch` 经 `friendlyError` 转中文提示后 `process.exitCode = code` 退出。
- 对外部命令（`npm`、`curl`、`ffmpeg`、`git`、`ISCC.exe`）一律通过 `child_process.spawn/spawnSync` 或 PowerShell 函数调用，并在非零退出码时抛出包含命令信息的错误。
- PowerShell 脚本使用 `Assert-WorkspaceChild` 校验目标路径位于仓库根之下，避免意外修改外部文件。
- Windows 安装包构建时通过显式 `relativeFile` / `relativeDir` 白名单列表收集产物，新增文件必须同时加入该列表与 CI 的 Parse 矩阵，否则构建会因缺少文件而失败。
- 测试与冒烟脚本使用隔离的 `--data-root`（默认在 `os.tmpdir()` 下按 PID+时间戳生成临时目录），并在 finally 块中清理数据与 fixture，保证幂等可重跑。
