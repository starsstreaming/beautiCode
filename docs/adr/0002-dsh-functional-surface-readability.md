# ADR 0002：DSH 功能面板独立保证遮挡

- 状态：接受
- 日期：2026-10-03
- 关联问题：[#78](https://github.com/starsstreaming/beautiCode/issues/78)、[#79](https://github.com/starsstreaming/beautiCode/issues/79)

## 背景与证据

在官方 DSH Desktop 0.2.0-rc.2、beauticode-dsh 1.0.26 中，深色与浅色设置面板均透出后方会话文字。向上滚动长会话时，正文和代码块也透过固定消息编辑栏。设置是 body 下的 portal，面板使用 `--dsw-alias-bg-layer-2`；编辑栏使用 `--dsw-specific-input-major` 并带 `data-composer-card`。

原样式在 body 上改写宿主 token，部分采用混合比例，部分硬编码 alpha；会话阶段、背景阴影与画窗又覆盖这些值。将所有层级统一到一个比例仍无法保证浮动面板能遮住后方文字。

## 决定

新增独立 `readability.js`，拥有功能面板保护样式和布尔偏好。现有 `/__beauticode/client.js` 按顺序提供它和媒体客户端，保持页面注入协议及鉴权不变。背景控制台仅通过 `BeauticodeReadableSurfaces.get/set` 读取和修改偏好。

背景启用时，默认将 dialog、alertdialog、menu、listbox、tooltip 与 `data-composer-card` 的底色设为不透明，并在这些元素上独立声明所需表面 token。规则依赖角色和宿主语义属性，不使用构建生成的类名；局部声明不会被会话阶段、阴影或画窗的 body 规则覆盖。浅色和深色使用各自的宿主静态色板。

### 补充：待交互面板（提问 / 计划审核 / 授权确认）

上述按角色枚举的保护漏掉了 DSH 的待交互面板。用户提问、计划审核与授权确认三者的卡片**都不带 dialog 角色**，且都以 `var(--dsw-specific-input-major)` 作为底色——正是本模块改写为半透明的那个 token，因此会话正文会透出提问卡片。

三者的 DOM 形状一致：外层是一个负责左右留白、自身透明的 flex frame，内层卡片才是绘制底色的元素。frame 上带稳定语义键 `data-question-key` / `data-plan-review-key` / `data-approval-key`，内层卡片分别是 `section`、`section`、`div`。因此保护选择器按「frame 的语义键 + 直接子元素」书写，即 `[data-question-key] > section` 等三条。

必须指向内层卡片而非 frame：若命中外层 frame，其左右内边距会被涂成一条实心横带。同样不使用类名——`mAtvLq_card`、`P2izSq_card`、`j_8BDW_card` 都是构建生成的哈希。三者都没有 dialog 角色，这既解释了漏网原因，也说明不能靠角色兜底，须随宿主新增待交互面板同步补齐。

用户可在背景设置中关闭「功能面板不透明」，恢复原有透明效果。偏好使用独立 localStorage 项，只有明确的 `false` 关闭保护；无效值或存储失败默认保护。偏好变更通过事件同步当前控制台，同源窗口通过 storage 事件同步。背景未启用时不改变宿主表面。

## 验证与限制

- 浏览器回归脚本 `scripts/dsh-readability-smoke.mjs` 在修复前因设置底色 alpha 为 0.32 而失败；验证深浅主题、hero/active/settling/无匹配阶段、阴影偏好、画窗的 32 种组合及关闭开关后的透明效果。
- 单元测试覆盖默认值、显式关闭、无效输入、存储失败、跨窗口变更、重复加载与控制台开关。
- 必须在真实 Desktop 上复查设置和滚动会话编辑栏，自动化 fixture 不替代现场验收。
- 本次通过官方 Desktop 的插件管理命令安装本地修复包后验收：画窗背景、0% 阴影下，浅色与深色设置均遮住会话文字；关闭开关立即重现叠字，重新开启后消失；滚动长会话时消息编辑栏遮住后方正文。保留默认保护开启。
- 本机旧安装使用共享背景目录，而当前源码默认使用 DSH 宿主目录。现场测试在备份 Desktop profile patch 后，通过插件已有的 `tokenFile` 配置继续指向旧目录；重启确认原有 7 项背景恢复。此项只调整本机测试配置，不修改数据迁移逻辑，原目录内容未删除。
- 保护依赖当前 DSH 的角色及 `data-composer-card` 契约；宿主移除这些语义标记时须随适配更新，禁止用 hash 类名兜底。

### 待交互面板补充验证

- 冒烟脚本 `scripts/dsh-readability-smoke.mjs` 的 fixture 增加提问、计划审核、授权确认三个面板（frame + 内层卡片），断言在原有 32 种深浅主题/阶段/阴影/画窗组合下，六类表面 alpha 均为 255；并断言三个 frame 自身保持 `rgba(0,0,0,0)`，防止误涂留白。
- 单元测试新增一例，断言三条子元素选择器存在、且不会命中外层 frame。
- 现场验收：官方 DSH Desktop，背景启用（画窗、0% 阴影）下打开提问窗口，卡片底色与会话输入框一致，正文不再透出；关闭「功能面板不透明」后立即恢复半透明，重新开启后再次遮挡。

### 补充：独立插件页（#92，2026-10-11）

Web 与官方 Desktop 的插件页共用 `readability.js`。以 `data-plugin-panel` 为边界，为直接页头、`data-plugin-group` 分组、`data-plugin-detail` / `data-plugin-item-detail` / `data-plugin-row-detail` 详情和 `data-plugin-config` 配置区域铺独立底板；`data-plugin-loading`、直接空状态段落及包含直接 alert 的错误／重试容器同样受保护。页面外框仍透明，保留分组间隙和外围壁纸。结构依据官方 Desktop 0.2.0-rc.2 的 ui-plugin-manager；宿主改变这些语义属性或状态根结构时须更新适配与 fixture，不使用 hash 类名兜底。

底板沿用 `--bc-readable-fill` 的宿主深色静态色／白色，alpha 为 1；局部表面 token 防止画窗规则覆盖。卡片使用同色底板覆盖负边距突出部分，并用宿主 hover token 作渐变叠层，保留 hover 反馈和焦点轮廓。沿用宿主圆角，不改变尺寸、间距、命中区域、拖动属性或滚动。只在启用背景且开启保护时，将页内 tertiary / caption 标签 token 提升为 secondary；主文字配色保持宿主值。官方主题下普通文字验收目标为 4.5:1。

不新增依赖、材质配置、采样或 DOM 观察器；CSS 自动覆盖异步新挂载内容。原默认值、显式关闭选择、存储格式、跨窗口同步、注入协议及鉴权保持原契约。关闭保护或清除背景即撤销这些样式，版本回滚恢复旧插件包。

`plugin-readability.browser.test.mjs` 用真实语义结构和主题色板覆盖深浅主题、会话阶段、画窗、阴影／磨砂，验证局部不透明、文字对比度、异步状态、关闭／清除恢复、负边距、hover、键盘焦点及控制区域。`plugin-readability-pack.test.mjs` 验证 Web 与 native Desktop 鉴权路径均提供当前共享脚本，并比较独立包和桌面聚合包的 DSH runtime。浏览器 fixture 不替代真实 Web 和官方 Desktop 候选包验收；结果与截图见 [#92 验收记录](../verification/issue-92-plugin-readability.md)。

### 补充：插件页改回透明底（#92 复审，2026-10-18）

独立插件页的实色底板解决了 #92 的对比度问题，但代价是整页被涂成实心色块：用户实测该底板占插件页 73.4% 像素、5×5 局部标准差 0.00，而「自动化任务」等同级页面在同区域标准差为 0.22–1.32（透出壁纸），观感割裂，用户明确要求回到透明底。

因此改为：插件页不再进入不透明名单，继续使用 `client.js` 发布的半透明表面令牌（`--bc-surface-mix`、`--dsw-alias-bg-base:rgba(17,20,27,.10)` 等），壁纸直接透出。可读性改由两项不遮挡背景的辅助承担：页内说明文字与计数提升到次要文字色；页面文字加一层随主题取色的柔和光晕（`--bc-text-halo`，深色 `#000`、浅色 `#fff`，`0 1px 2px`、45% 透明度）。两项辅助同样受「功能面板不透明」开关与 `data-bc-active` 约束。角色面板（dialog／menu／tooltip／composer、提问／计划审核／授权确认）的保护不变，`--bc-readable-fill` 及其局部令牌仍只服务这些面板。

取舍必须写明并**明确接受**：透明底不再具备「任意壁纸上都 ≥4.5:1」的保证，这是几何上的必然——纯白壁纸上的浅色文字无法靠文字色或光晕达标。约束是**分主题**的、且互为镜像：深色主题（浅色文字）要求局部背景保持偏暗（L ≲ 0.10；实测 #555555 L≈0.091 时标题 7.13:1、正文 4.95:1）；浅色主题（深色文字）要求局部背景保持偏亮（L ≳ 0.81；实测 #e8e8e8 L≈0.807 时标题 15.42:1、正文 4.73:1）。越界极值——深色主题遇纯白壁纸 1.05:1、浅色主题遇纯黑壁纸 1.11:1——由回归测试显式断言**失败**，把取舍钉在测试里而不是让门槛空过。参考页（自动化任务）实机为标题 5.31–5.61、次级文字 4.31–4.39；正文达标依赖上述色阶提升（不提升时深色 3.49:1、浅色 3.02:1）。若日后需要「任意壁纸都达标」的强保证，只能回到局部底板或引入用户可选的底板强度，光晕无法替代。

验证：`plugin-readability.browser.test.mjs` 改为断言透明（alpha 0）、光晕随主题取色并被文字继承、说明／计数提升一档、白黑壁纸下页面截图必须不同（壁纸确实透出）、hover 仍是宿主半透明反馈；`readability.test.mjs` 增加源码级守卫，禁止不透明名单重新出现 `[data-plugin-panel]`。数值证据见 [#92 验收记录](../verification/issue-92-plugin-readability.md)。

### 补充：面板不透明度改为 0–100% 强度（2026-11-09）

原实现只有布尔偏好：开启时把六类面板的底色写成 alpha 1 的静态色板，关闭时整条局部声明不匹配、回到宿主半透明。用户要求像「背景阴影」「背景磨砂」一样可自定义调节。

决定：三个旋钮保持彼此独立，但把「功能面板不透明」从布尔改为 0–100 强度。`--bc-readable-fill` 改为 `color-mix(in srgb, 色板 calc(var(--bc-readable-strength,100) * 1%), transparent)`，强度写在 `<html>` 的 `--bc-readable-strength` 上；0 不设置该变量且沿用 `data-bc-readable-surfaces="false"`，使选择器整体不匹配，外观与旧「关闭」完全一致；100 与旧「开启」一致。存储键不变：旧 `"false"` 读成 0，旧 `"true"`、缺失或无效值读成 100；写 0 时仍写 `"false"`，让版本回滚后的旧包仍读到关闭语义；中间值写数字，旧包读数字视为开启（保守方向）。控制台由「已开/已关」按钮改为滑杆 + 重置箭头，与阴影、磨砂共用行结构与样式。

取舍：0% 回到宿主半透明（与旧关闭一致）；1–99% 时面板逐级透出壁纸，背景阴影与磨砂（只作用于壁纸）会透过半透明面板显现，但不会模糊面板后的会话正文——若要「半透明仍遮住正文」，只能提高强度或另加 `backdrop-filter`；本次不引入后者，避免包含块与视频背景性能代价。验证：单元测试覆盖默认值、旧布尔迁移、数值夹取、无效输入、存储失败、跨窗口同步与新强度变量；浏览器回归断言 100% → alpha 255、40% → alpha ≈102、0% → 宿主半透明；控制台测试覆盖滑杆写入、重置与三个重置箭头的样式一致性。

## 回滚

用户关闭开关即可回到原有透明效果。版本回滚可移除脚本的拼接、打包项与控制台入口；独立偏好不会影响旧版背景客户端。不会改写 DSH 安装文件或原有背景状态。
