# ADR 0003：宿主主题与背景透明度独立管理

- 状态：接受
- 日期：2026-10-03
- 范围：Codex、WorkBuddy、Cursor、豆包；DSH 保留 ADR 0002 的保护并参与回归。

## 复现与根因

用户在浅色模式中发现文字被背景干扰，并提供了背景清单中的原始错误提示。浏览器回归使用实际渲染载荷和适配层已有的 DOM 契约，系统设为深色，应用切至浅色，背景阴影为 0、面板透明度为 100%。修复前四个非 DSH 适配层均失败：Codex 未跟随宿主主题，Cursor 只读 body 的类名，豆包只读 html 的属性，WorkBuddy 的部分样式只匹配 `html.light`。此外，全透明的正文和侧栏没有独立阅读衬底。

提示来自内部 `Live verify did not pass ...` 错误。Codex 控制台的返回边界直接传回原始错误，使内部事务阶段出现在界面。

## 决定与边界

宿主继续拥有文字颜色；背景色调作为媒体偏好保留。功能区域的底色跟随宿主主题，不能由系统深浅偏好、媒体色调或阴影浓度决定。

- Codex 的主题监听放入独立 renderer 模块，由载荷入口安装。读取 html/body 的主题标记，宿主没有明确标记时才使用 color-scheme 或系统偏好。忽略正文和 hover 的无关 DOM 变更，销毁运行时后释放监听。浅色正文和侧栏保留白色 82% 衬底，语义浮层和输入表单不透明。
- WorkBuddy 用独立主题选择器覆盖 chat-shell 与 VS Code 的浅深色别名，应用到 portal、蒙版和阅读区域。读取当前主题 token 时同时考虑 body。浅色正文和侧栏的不透明度至少 82%；功能浮层与消息编辑栏使用不透明宿主底色。其余已有 token 透明体系保留。
- Cursor/豆包继续共用 Desktop CDP 渲染器，宿主契约提供阅读区和固定输入区的选择器。主题识别覆盖 html、body 和 Cursor workbench；显式宿主标记优先于系统。Cursor 的高对比度浅色单独匹配。浅色阅读区保留至少 82% 衬底，高对比度阅读区不透明。
- DSH 保留现有默认开启的功能面板保护及关闭开关，不重复改写它的主题机制。

只有背景活动时启用新增阅读保护。模式切换只更新属性或 CSS，不重建图片、视频或 blob URL。WorkBuddy 原有透明外壳规则在清除背景后仍存在；本次只保证新增功能浮层保护随背景关闭释放，不将旧透明体系重写为新契约。

用户提示统一为「正在媒体验证中，请等待30s再次导入」。转换发生在用户界面边界，保留内部校验结果、事务阶段和失败回滚。此文案调整不新增延迟、自动重试或改变内部失败状态。

## 验证与限制

`scripts/host-theme-smoke.mjs` 使用已有 Playwright 与 Chromium/Edge 运行五端真实载荷，验证浅→深→浅、系统深色与应用浅色不同步、零阴影、最大面板透明度、文字对比度、编辑栏遮挡、媒体舞台不重建，以及保护随清除释放。另验证 Cursor workbench 的高对比度浅色和 Codex 监听释放。DSH 的 32 种阶段/阴影/画窗组合另行回归。

脚本第三个参数可指定 `desktop-aggregate` 解包目录，直接验证包内 runtime 与新增主题模块，避免源码验证通过而安装包漏文件。该参数不安装软件或操作用户的宿主状态。

这是基于宿主语义 DOM 的浏览器回归，并非五个已安装应用的现场验收。宿主升级后若移除角色、主题标记或契约中的阅读区域选择器，仍需现场检查并更新相应适配层；不新增 hash 类名兜底。回滚可移除各适配层新增阅读样式和主题接线，已有媒体状态与背景档案不变。
