# ADR 0007：画窗消费背景偏好并保留宿主滚动布局

- 状态：接受
- 日期：2026-10-05
- 关联问题：[#86](https://github.com/starsstreaming/beautiCode/issues/86)、[#87](https://github.com/starsstreaming/beautiCode/issues/87)

## 背景与证据

画窗使用独立图片与水波 canvas，普通媒体舞台在此模式下不可见。现有偏好写入端
正确更新 `--bc-bg-blur` 和 `--bc-dim`，但画窗没有消费它们，因此滑块数值更新而画面不变。

两处 `[class*="_fade"]{display:none!important}` 规则也误隐藏宿主内容容器。
官方 Desktop 0.2.0-rc.2 把 fade 类附加在滚动 body 上，原本仅定义渐隐 mask。
ResizeObserver 依据溢出添加类，隐藏后的零高度又让宿主移除类，产生反馈循环。
已有静止长思考在 180 帧中变化 179 次，90 帧高度为零；删除两处规则后稳定为 400px，
恢复规则则再次出现。这不是必须依赖流式输出或水波动画的故障。

## 决定与边界

画窗渲染层复用现有偏好变量和数据属性。模糊仅作用于背景图片，阴影通过画窗的
伪元素覆盖图片与水波；按宿主解析出的深浅色选择黑或白，前景保持清晰。
偏好写入、存储、媒体协议和宿主主题管理保持原有职责。

直接删除 client.js 和 atmosphere.js 的全局 fade 隐藏规则，保留宿主 mask 和
ResizeObserver 所依赖的内容布局。不增加哈希类名白名单、兼容层或观测器补丁。

## 验证、限制与回滚

新增真实浏览器测试先在原始脚本上失败，覆盖画窗磨砂、深浅色阴影、归零、关闭画窗
后的图片与视频恢复，以及普通/画窗模式下原生渐隐内容的高度和滚动位置。
完整工作区测试 397 项通过，1 项既有 Task Scheduler 现场测试跳过；类型检查通过。
浏览器运行时由环境变量显式指定，未指定时明确跳过，生产插件没有新增依赖。

源码修复包在官方 Desktop 中冷启动，实际 CSS 与源码摘要一致，没有临时覆盖样式。
长思考及滚动、普通图片、3840×2160 实际播放的视频均在 180 帧观测内保持稳定；
滑块与深浅色生效。短时已完成会话验收不替代长期压力或新请求流式验收。

发布按用户要求以最新 registry 的 1.0.28 为基线，仅叠加两个修复、README 说明
与版本号 1.0.29。已发布包保留其余 45 个文件的字节及全部文件权限，避免带入完整
源码重新打包时的其他差异。registry 下载包的 SHA-1 与 SHA-512 均与实测 tarball
一致，49 个文件齐全，`latest` 已指向 1.0.29。本地 Desktop 通过官方插件命令安装
正式版本，逐文件摘要一致。精确覆盖补丁、逐文件摘要和发布核验保存于
`docs/releases/beauticode-dsh-1.0.29/`。

不需要数据迁移。回滚可安装已发布的 1.0.28，偏好和保存的背景不受影响；它会恢复
本次已确认的滑块失效和长内容抖动。Desktop 原插件及 profile 配置已有本地备份。
