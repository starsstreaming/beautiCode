# ADR 0008：Codex 初始化阴影与输入区装饰层

- 日期：2026-10-23
- 状态：接受
- 范围：Codex adapter；保持现有背景档案、存储键及其他客户端行为。

## 问题与证据

用户报告初始化阴影与设置不符，并提供输入框外围黑色矩形截图。
现场 Codex 包版本为 26.1016.6573.0，CDP 与探索下的背景入口可识别。
读取现场时保存值、API、根节点 CSS 变量及清单都为 46%，背景未活动；这次快照不代表已经复现真实客户端的启动时序。

浏览器回归使用真实媒体载荷，复现两个初始化缺口：只有控制台负责恢复阴影，独立媒体启动不恢复；宿主替换 html.style 后，界面仍显示 46%，媒体阴影却回到 0%。
现场还发现 composer 后有空的、不可交互、绝对定位的 bg-surface 元素；现有样式没有清除它的底色，与用户截图一致。生成的 CSS 模块哈希不作为适配契约。

## 决定

将阴影偏好的读取、校验、持久化及 CSS 同步移入独立 dim.js，媒体初始化前安装，控制台仅调用同一 API。继续使用 beauticode-dim 存储键与 0～1 值域，0 是有效设置，非法值回退自动。

只监听 html 的 style 与 data-bc-dim-user 属性。幂等写入避免自身触发循环；重复安装复用同版本实例，替换版本释放旧监听。窗口关闭结束生命周期，清除媒体保留用户偏好供下次应用。自动滑块位置分别对应深色 0%、浅色 48%。

只在背景活动时，将 main 内底部定位容器的空、不可交互 bg-surface 子装饰层设为透明。输入框、对话框和其他 surface 保留底色；清除背景恢复宿主样式。不引入通用 surface 透明规则。

2026-10-26 补充：用户继续报告输入框上方的黑色渐变。现场确认它属于 thread-scroll-container 内 sticky bottom-0 页脚的空、不可交互、横向绝对定位 from-surface 子层；实际背景为从 #181818 到透明的线性渐变。旧的 bg-gradient-to-t/from-token-main-surface-primary 规则不匹配该结构。新增仅针对这一布局职责的规则，不依赖 _background_ / _fade_ 生成类名，不改变有内容的节点、非粘滞结构或聊天区之外的渐变。背景清除后由 data-bc-active 门控恢复宿主渐变。

## 验证与边界

appearance.browser.test.js 使用 Edge 实际渲染，覆盖首次恢复、根样式替换、零值、非法值、浅深色、清除偏好不重建舞台及输入区边界。通过 BEAUTICODE_PLAYWRIGHT_MODULE 指向已有 Playwright 运行时；没有运行时时显式跳过，不添加发布依赖。

其他客户端现场均未运行，安装状态不能代表新版 DOM 验收。另一个已有五端浅色检查发现，四个非 DSH 客户端默认 48% 白色遮罩在纯黑壁纸上只有约 3.75:1 对比度，本次保留既有亮度策略，未将其宣称为通过。

回滚可恢复安装目录 current.json 指向上一版本，再重启 beautiCode 辅助进程；无需重启或修改 Codex 二进制。源码回滚同时恢复 payload、console、CSS 并移除 dim.js，原存储键无需迁移。
