# Linux 桌面进程身份与启动项所有权

日期：2026-10-29。状态：采用。关联：[PR #98](https://github.com/starsstreaming/beautiCode/pull/98)。

## 背景与目标

Linux 桌面守护会在进程启动的十秒窗口内自动重启未开启 CDP 的客户端。
独立 Codex CLI 也叫 `codex`，只匹配文件名会误终止 CLI。
此外，Desktop Entry 的 Exec 值需要两层转义；拿原始路径做子串匹配会使含
`%`、`$`、引号或反斜杠的自身启动项被误判为外来文件。Cursor 原来的安装、
卸载路径则完全没有所有权检查。

## 决策与边界

- Codex 进程发现只接受 `codexInstallCandidates(..., "linux")` 中桌面安装路径的
  规范化实际文件路径，继续排除 renderer、app-server 和同镜像子进程。
  未识别的手工安装采用保守策略，不进入自动终止流程；新增安装布局时需要显式增加候选与回归测试。
- `processes.ts` 负责宿主身份和进程快照，`launch.ts` 负责端口、启动及连接编排，
  `startup-policy.ts` 负责启动窗口与去重，`startup-repair.ts` 负责监听及自动修复。
  包入口继续提供原有接口；删除内部旧路径的实现，不增加兼容转发层。
- `scripts/xdg-autostart.mjs` 是 Codex 与 Cursor 共用的启动项文件边界。
  所有权必须同时匹配 Desktop Entry 分组中唯一的管理标记和完整 Exec 命令；
  命令比较复用生成器的 `desktopExecQuote`，包括 host 与 PID 文件参数。
- 安装与卸载在停止守护、清理页面前先校验启动项。新文件用硬链接发布以避免覆盖
  并发出现的外来文件；事务回滚也经过相同所有权检查。冲突向调用方报告，不静默删除。
- 打包与安装必须一并携带共享模块及其 portable-runtime 依赖；源码检出与独立分发
  有不同目录布局，沿用本项目已有的运行时模块解析方式。

## 验证与回滚

回归覆盖独立 CLI、CLI 与桌面同时运行、未知同名程序、桌面子进程、特殊路径的
安装/重装/卸载，以及外来启动项保护。测试仅使用进程快照和临时用户目录。
全量测试、类型检查和两种平台的包暂存验证共同约束分发行为。
不改变持久化主题格式、稳定包入口或 Windows 启动协议；回滚本修复不需要数据迁移。
