# 豆包工作桌面背景适配

豆包工作是独立于普通豆包的 Windows 客户端。本适配针对 [Issue #99](https://github.com/starsstreaming/beautiCode/issues/99)，复用桌面 CDP（Chrome 调试协议）运行时，但使用独立的进程、端口和主题状态。

## 使用方式

源码工作区中可使用 `npm run doubaowork:setup -- install|status|uninstall`。打包后的 `beauticode-desktop` 提供对应的 `doubaowork install|status|health|uninstall` 命令。卸载守护程序保留主题状态和原始媒体文件。

背景设置挂在豆包工作的「设置 → 外观设置」中，包含功能面板不透明、阴影、磨砂、声音、导入、已保存背景、皮肤中心、本地壁纸库和清除。功能面板默认保留宿主底色；用户可以选择让其透明。

图片与视频主题记录原文件路径，导入时默认使用不含扩展名的文件名。Wallpaper Engine 项目的视频使用项目中的视频文件；`scene` 项目目前只显示项目预览图，**不解析或播放 `scene.pkg`**。本地壁纸库从 Steam 配置发现，扫描时保留已有壁纸绑定。

## 运行边界

- 默认端口为 `9346`，另有固定候选端口 `9356`、`9366`、`9376`；调试连接仅使用本机回环地址。
- 目标仅限经过验证的 `doubaowork` 聊天页面，缺少宿主锚点时停止注入。多个候选页面存在时，运行时选择面积较大的页面。
- 用户从原图标启动客户端后，守护程序仅对新启动、未启用 CDP 的主进程尝试一次修复。进程身份包含 PID 和创建时间；若出现替代主进程，则保留它而不继续追杀。用户关闭客户端后，守护程序不会主动重新打开它。
- 启动修复的进程关闭命令和退出等待均有上限。超时或关闭失败会写入宿主日志；这不代表目标页已经验证或注入成功。
- 主题与运行状态位于 `%LOCALAPPDATA%\beautiCode\hosts\doubaowork`，与普通豆包分开。壁纸项目描述中的视频路径必须留在该项目目录内，媒体仍需通过现有文件校验。

## 验证状态

截至 2026-11-06，构建、类型检查、适配器及聚合包测试已运行；本机已验证守护安装、状态查询和本地壁纸库扫描。用户从原图标重新打开客户端后，守护完成受控重启，CDP 连接和背景入口恢复；可见聊天页的九项设置均已注入，当前视频背景也已解码并持续播放。

这些检查尚未覆盖设置中的图片、场景预览、主题切换和浅深色可读性，也未重新操作全部控件。不要将静态场景预览视为动态场景播放。
