# 隔离场景渲染实施计划

> 继续执行用户已确认的五端背景设计；在现有工作区实现，不提交、不覆盖其他工作区。

**目标：** 将 DSH 原型中实际渲染 Scene 的能力提取成共享运行时，用合成项目验证真实 WebGL 首帧、生命周期及脚本隔离；此阶段不接入任何真实宿主的用户数据。

**架构：** 可信父页面读取经授权的本机包和固定构建产物，向 `sandbox="allow-scripts"` 的不透明源 iframe 通过一次性 MessageChannel 只传字节与项目文档。子页面关闭 SceneScript，父子之间只传生命周期命令、首帧、心跳及不含敏感内容的错误。父页面保留旧背景，调用方只在首帧通过后自行提交。发现跳过的脚本时拒绝或终止，不把降级结果当作兼容的场景。

**依赖：** `webwallgl@3.0.0` 和 `esbuild@0.25.12`，版本沿用已有 DSH 原型；保留渲染质量修补的漂移检查与第三方许可。

**约束：** 资源 URL 必须是带临时令牌的精确回环地址；不允许网络通配或将令牌交给 iframe。挂载失败、取消、超时、页面销毁及上下文丢失必须释放资源。SceneScript 可被惰性发现，首次就绪后仍持续检查；后续宿主集成须处理运行中失败与回滚。浏览器夹具与真实宿主证据必须分开。

## 审查重点

- 模拟不可信的消息来源、重复初始化、过大资源及延迟出现的脚本。
- 首帧之前失败、首帧之后失效、取消和页面隐藏时的资源释放与可观察错误。
- 构建与许可文件完整；资源 URL、项目绝对路径和访问令牌不进入隔离页面。
- 渲染器未完成宿主集成前，不声称五端动态场景已经可用。

### Task 1: 帧运行时

- 先写测试并观察缺少运行时的失败；覆盖正确的父页面初始化、真实首帧回执、关闭 SceneScript、跳过脚本立即失败和迟到发现脚本后的失败、暂停/恢复、销毁、上下文丢失。
- 提取 DSH 原型并修改边界：固定关闭脚本、仅发送受限错误码；在运行过程中检查脚本状态并发送心跳。
- 运行帧运行时测试，确认失败路径不泄露内容且能够释放实例与 Blob。

### Task 2: 父页面播放器

- 先写测试并观察缺少播放器的失败；覆盖 URL 与元数据校验、大小限制、沙箱 CSP（内容安全策略）、取消、超时、单次握手、错误与心跳超时。
- 实现或有选择地迁移父页面播放器，调用方提供受控包和 bundle URL，持有的令牌和路径不传入 iframe。
- 运行播放器测试与帧测试，确认前后端协议一致。

### Task 3: 构建、许可和浏览器验证

- 安装固定依赖并增加 workspace 构建及测试入口，不删改已有 Linux、豆包工作工作区配置。
- 用合成 Scene PKG 在 Chromium 中验证真实 WebGL 首帧、画布尺寸、脚本禁用、错误释放；区分真实宿主验证。
- 验证 bundle、第三方许可、核心测试和 `npm run typecheck`；后续再接入豆包工作和其他宿主。
