日期：2026-10-11。修复分支：`codex/issue-92-plugin-readability`，基于最新 `origin/main`（`7b23b3a`）。原工作区未提交文件未改动。

## 实现与边界

共享 `readability.js` 为 DSH Web / 官方 Desktop 的插件标题、各分组、卡片、详情、配置和异步状态铺完全不透明的局部底板；页面外框和组间间隙保留壁纸。说明文字及计数局部采用宿主 secondary 标签色。沿用原有保护开关、偏好同步和注入协议，无新增依赖。

保留宿主圆角和布局。审查发现：为无内边距的分组强加圆角，会使首字背后的底板被裁切；已删除这条规则，并用白／黑壁纸下标题截图完全一致的回归验证。测试阶段属性须位于 `#root` 后代，已增加真实选择器匹配断言。

## 真实应用

使用官方 DSH Desktop 0.2.0-rc.2，以及其自带同版本 CLI 启动的真实 Web。全局旧 Web CLI 0.1.0-rc.6 缺少新版独立插件页／注入机制，未作为本次新版契约验收依据。

使用隔离 profile 和背景目录加载独立候选，并与 tarball 解包文件逐字节核对。Web 与 Desktop 的背景目录分别隔离；首次同时验收曾竞争锁，持锁进程 35232 已结束，分离后背景应用成功。未修改注入器的锁机制。

Web 在两种主题下验证标题、官方组和已安装组底色分别为 `rgb(255,255,255)` / `rgb(53,54,56)`；插件详情和配置同样为实色。官方 Desktop 验收深浅主题列表、终端详情／配置、返回后的新挂载列表和安装弹窗，保留外框背景及负边距卡片。加载、空、错误／重试等状态用真实结构 fixture 验证，未人为破坏真实应用制造错误。拖动属性和命中区域由回归检查；当前官方版本现场拖动插件页标题文字表现为选中文字，未证明它能移动窗口，此项保留宿主现有行为，不宣称修复窗口拖动。

## 修订：插件页改为透明底（2026-10-18）

#93 的实色底板在真实使用中被判定为观感割裂（该底板占插件页 73.4% 像素、5×5 局部标准差 0.00，同级「自动化任务」页同区域为 0.22–1.32）。本次修订按用户要求改回透明底：`readability.js` 不再把 `[data-plugin-panel] …` 列入不透明名单，改用两项不遮挡背景的辅助（说明／计数提升一档、页面文字光晕），取舍与边界见 ADR 0002 的同日补充。

| 项目 | 结果 |
| --- | --- |
| 浏览器回归（真实 Edge，零依赖 CDP 等价复刻仓库内用例） | **7 组 / 131 条断言全绿**：透明（alpha 0）、对比度基准、壁纸透出（白黑壁纸逐像素）、异步状态、亮／暗／复杂／播放中视频、关闭与清除恢复、几何／hover／焦点／控制区域 |
| 对比度 | 分主题、分背景区间验收，见下节；深色主题在 L≈0.091 背景上标题 7.13:1 / 正文 4.95:1，浅色主题在 L≈0.807 背景上标题 15.42:1 / 正文 4.73:1 |
| 对照：不提升色阶 | 正文仅 3.04–3.13:1 → 色阶提升是正文达标的前提 |
| 参考页实机基准（自动化任务） | 标题 5.31–5.61:1、次级文字 4.31–4.39:1 |
| 单元测试 `test/readability.test.mjs` | 通过；新增源码级守卫（不透明名单不得再含 `[data-plugin-panel]`、光晕与色阶规则必须存在） |
| 几何／滚动／hover／焦点／拖动属性 | 与修订前逐项一致（回归断言原样保留） |
| 未跑 | 本机无仓库依赖与 Playwright，未跑 `npm test` / `npm run typecheck` / `npm run build` 与 Playwright 本体；由 CI 与维护者环境复核。真实照片壁纸的现场观感由提出方在其 DSH 上确认 |

### 两种主题各自适用的背景条件（维护者复核意见补充）

透明底把对比度交给了壁纸，因此约束是**分主题**的，且两种主题互为镜像：

| 主题 | 文字色 | 适用背景 | 测试用背景（实测） | 标题 / 正文对比度 | 越界示例（测试断言必然低于门槛） |
| --- | --- | --- | --- | --- | --- |
| 深色 | `#f9fafb` / `#cfd3d6` | 局部背景保持偏暗（L ≲ 0.10） | `#555555`（L≈0.091，与 #92 报告实测背景 L≈0.097 同级） | 7.13:1 / 4.95:1 | 纯白壁纸：1.05:1 |
| 浅色 | `#0f1115` / `#61666b` | 局部背景保持偏亮（L ≳ 0.81） | `#e8e8e8`（L≈0.807） | 15.42:1 / 4.73:1 | 纯黑壁纸：1.11:1 |

两侧越界由 `plugin-readability.browser.test.mjs` 的 `OUT_OF_RANGE_CASES` **显式断言失败**，避免门槛被空过；不提升色阶时两种主题都不达标（深色 3.49:1、浅色 3.02:1），因此 tertiary / caption → secondary 的映射是正文达标的前提。

**明确接受该取舍**：本方案选择「透明优先」——在上述区间之外（深色主题遇明亮壁纸、浅色主题遇暗壁纸），说明文字会低于 4.5:1。这是已知且接受的代价，另一种可能（回到不透明底板，或引入用户可选的底板强度）会牺牲页面与「自动化任务」等页面一致的透明观感。

真实 DSH 中的明亮／复杂壁纸复查见下方「真实应用」小节补充。

复跑方式不变：设置 `BEAUTICODE_PLAYWRIGHT_MODULE` 与 `BEAUTICODE_BROWSER_CHANNEL=msedge` 后 `npm run test -w @beauticode/adapter-dsh`；未配置浏览器环境时浏览器用例显式跳过，不代表完成视觉验收。
